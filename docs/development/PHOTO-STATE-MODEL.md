# Модель окна и изображения KDEGlance

Дата: 28 октября 2026. Версия приложения и пакета остаётся **1.0.0-5**.
Этот отчёт заменяет описание поведения фото в PHOTO-MODULE.md; остальные модули
и независимые группы настроек сохраняют прежнюю реализацию.

## Причины ошибок и карта ответственности

| Компонент | Ответственность | Исправленная проблема |
|---|---|---|
| `ImageView::wheelEvent`, `Geometry::zoomAt` | Единственный масштаб и локальное смещение, точка фото под курсором | Раньше колесо передавало размер хосту, который заменял масштаб результатом fit; зум прекращался у предела экрана |
| `ImageView::resizeEvent` | Fit при ручном resize; сохранение независимого масштаба при временном зуме | Во время одного wheel transaction промежуточный resize больше не пересчитывает исходное состояние |
| `ImageView::mouse*Event` | Alt — локальная панорама, обычный drag — запрос перемещения окна | Ранее назначения были противоположными; обычное движение могло сдвигать фото внутри окна |
| `PreviewWindow` | Размер viewport, ограничение размера окна рабочей областью, сохранение ручного размера | Явные источники `Automatic`, `Manual`, `Wheel`, `Compositor`; один лишь resizeEvent не разрешает сохранение |
| `Geometry::clampPan` | Границы панорамирования, центрирование помещающегося изображения | Локальные координаты не зависят от позиции окна на рабочем столе |
| `placement.js` | Первичное размещение, фокус, отчёт рабочих областей и состояния KWin | Убрано восстановление старого photo top-left при каждом resize: оно конфликтовало с отдельными уведомлениями о размере и позиции при tile/maximize |
| `ViewerApp::ReportPhotoWindowState` | Передача состояний KWin только текущей фотосессии | Сообщение со старым session ID игнорируется; старое окно не блокирует геометрию нового |
| `Settings::resetModule`, `resetActiveModule` | Уже существующий независимый сброс | Реализация других модулей не переписана; повторно проверена изоляция групп |

Контрольная точка в локальной Git-истории:
`before-photo-state-architecture-20261028`. История находится в
`.development-history`; обычная `.git` и удалённый репозиторий не изменяются.

## Правила состояний

1. Открытие без ручного размера: 100% (один пиксель исходника на пиксель экрана),
   ограничение рабочей областью. С ручным размером: восстановление ширины/высоты,
   fit без искажения, чёрные поля при несовпадении пропорций.
2. Колесо задаёт новый масштаб независимо от доступного размера окна. Окно следует
   размеру фото до ограничения экрана. Затем viewport сохраняется, фото продолжает
   увеличиваться. Технический предел обычно 32×; для крошечных оригиналов предел
   не ниже уже установленного fit. Масштабирование не создаёт увеличенную растровую
   копию на каждый шаг.
3. При уменьшении crop сначала уменьшается внутри прежнего viewport. Когда фото
   помещается целиком, окно уменьшается вслед за ним. Дробный масштаб сохраняется
   без округления к целым пикселям окна на каждом шаге.
4. Якорь вычисляется как `(cursor - offset) / scale` в координатах viewport.
   После изменения размера viewport смещение пересчитывается из исходного состояния
   этого события, затем ограничивается допустимой панорамой. Когда фото целиком
   и точно заполняет окно, свободной панорамы нет: ограничение краями имеет приоритет
   над невозможным смещением. Это также исключает искусственные пустые поля.
5. Обычный drag запрашивает `QWindow::startSystemMove`, не меняя масштаб/смещение.
   Alt-drag меняет только локальную панораму. Alt-drag за угол остаётся отдельным
   ручным resize с пропорциями фотографии. Без Alt resize свободный, фото вписано.
6. Сохраняется только явная ручная resize-сессия. Wheel, fit, pan, tile/maximize
   не записываются в сохранённый размер. Закрытие максимизированного фото и новое
   открытие возвращают ручную геометрию, временный зум и панорама сброшены.
7. В штатных состояниях tile/maximize приложение не пытается менять размер окна
   вслед за колесом. Масштаб фото при этом продолжает меняться внутри viewport.
   KWin управляет расположением фото после первичного открытия. Старые координаты
   не восстанавливаются поверх его переходов.
8. Загрузка лучшего разрешения остаётся асинхронной, с отложенным запуском после
   прекращения зума. На каждый шаг колеса нет ожидания композитора, повторного
   синхронного декодирования или D-Bus запроса Status. Отчёт KWin о managed state
   передаётся только при изменении состояния.

## Проверки

До исправления добавленный тест `wheelContinuesPastScreenAndPreservesCursor`
воспроизвёл отказ: `view->zoomScale()>scale` после достижения предела окна — FALSE.
После исправления он проходит.

Автоматические регрессии охватывают:

- увеличение сверх окна, курсор вне центра, возвращение от crop к уменьшению окна;
- сброс → закрытие → открытие → перемещение → колесо;
- отсутствие дрейфа масштаба при смене направления и pixel-only событиях;
- свободный квадратный viewport с чёрными полями, Alt-ratio, крошечные оригиналы;
- сохранение ручного размера отдельно от wheel и KWin, закрытие после maximize;
- устаревшие сессионные отчёты композитора;
- асинхронную смену модуля, отсутствие записей геометрии при KWin tile/maximize;
- сохранность независимого сброса и остальных работающих функций.

Сеансовый сценарий: `tests/desktop/check-photo-reset.py`. Он использует настоящий
Dolphin, Qt Wayland, KWin и отдельный XDG_CONFIG_HOME. Тестовый Qt-адаптер не
устанавливается в пакет. Штатная служба временно уступает D-Bus имя тестовому
процессу и восстанавливается при завершении. Проверяются натуральный/ручной размер,
wheel, локальный якорь, две разновидности drag, штатные KWin maximize и обе половины
экрана, сброс всех шести модулей, сохранность JSON-групп после перезапуска,
Space/Escape, восемь смешанных открытий/закрытий и жизнеспособность сервиса.

## Что проверено не полностью

Инъекция Qt-событий проверяет обработчики в настоящих Wayland-окнах, но не заменяет
физическое устройство ввода. Ручная проверка плавности мыши/тачпада, фактического
перетаскивания до электрических краёв и Alt-resize обязательна для пользовательской
приёмки. Проверка KWin вызывает его штатные maximize/tile операции для тестового
окна, а не имитирует попадание физического курсора в край экрана.

В текущей конфигурации KWin `CommandAllKey` не переопределён; системное значение —
Meta. Если пользователь назначит Alt системному перемещению, композитор может
перехватить Alt-drag раньше приложения. Клиент Wayland не может надёжно отменить
такой глобальный перехват. Глобальные сочетания/параметры KDE не менялись.

Привязка/максимизация не отключается. Использованы публичные
[операции и свойства KWin](https://develop.kde.org/docs/plasma/kwin/api/) и
[системное перемещение Qt](https://doc.qt.io/qt-6/qwindow.html#startSystemMove).
Сценарии физической приёмки: [MANUAL-ACCEPTANCE.md](MANUAL-ACCEPTANCE.md).
Один монитор доступен для сеансовых проверок; разные DPI/мониторы требуют отдельной
приёмки. SMB и запуск внешних приложений в этой итерации проверяются сохранёнными
автоматическими тестами; новая ручная SMB-проверка не заявляется.
